# 学生状态管理系统 · 部署说明

适用：Windows 10/11 x64，端口固定 `3210`。
发布包已经带前端产物和 Windows 预编译依赖，目标机不需要装编译环境。

---

## 一、全新安装（空数据）

1. 把 `student-status-board-1.0.0.zip` 拷到新电脑，解压到本地目录，例如 `D:\student-status-board`。
   - 路径带空格/中文可以，但**不要放 OneDrive、坚果云等同步目录**（SQLite WAL 会被同步搞坏）。
2. 右键开始菜单 → **终端（管理员）** 或 **Windows PowerShell（管理员）**，进入目录：

   ```powershell
   cd D:\student-status-board
   powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1
   ```

3. 按提示设置登录密码（至少 6 位，输入时不显示）。
4. 安装完成后桌面会出现「学生状态管理系统」快捷方式，双击即可启动；同时会建一个「重置登录密码」快捷方式。
   如果桌面快捷方式没建出来，项目根目录里的 `启动学生状态管理系统.cmd` 双击也能启动。

`install.ps1` 会依次做：

- 检测 Node.js ≥ 22；没有就从 npmmirror 下载 `v24.22.1` 到 `runtime\node`
- 安装生产依赖（发布包已带 `node_modules`，通常直接复用）
- 首次运行引导设置登录密码
- 在桌面创建一键启动快捷方式
- 监听 `0.0.0.0`，`COOKIE_SECURE=auto`（HTTPS 自动加 Secure，局域网 HTTP 不加）
- 放行防火墙 TCP 3210（仅 `LocalSubnet`，不暴露公网）
- 检测 Tailscale；已安装且已登录时执行 `tailscale serve`
- 注册每天 03:00 的 SQLite 备份任务
- 冒烟检查 `/api/healthz`

默认**不注册 Windows 服务、不开机自启**。需要后台常驻时加 `-InstallService`，服务也是手动启动。

## 二、整目录搬迁（数据、密码、API Key 全带走）

1. 旧电脑先停止服务：双击 `停止学生状态管理系统.cmd`。
2. 把旧电脑整个项目目录复制到新电脑，**必须包含 `data\`**：
   - `data\app.db`：学生、反馈、生成历史
   - `data\config.json`：登录密码哈希
   - `data\backups\`：每日备份和导入前快照
3. 新电脑管理员 PowerShell 进入目录，跑一次：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1
   ```

已有 `data\config.json` 时会跳过设密码，密码、数据、服务器里加密的 API Key 都原样可用。

> 旧电脑和新电脑不要同时运行同一份数据；需要两边都用时，用 JSON 备份导入到其中一边。

---

## 三、只搬业务数据（JSON 备份）

1. 新电脑按「一、全新安装」装好并设置新密码。
2. 旧电脑：设置页「备份与恢复 → 导出全部」，得到 `student-status-board-YYYY-MM-DD.json`。
3. 新电脑：设置页「备份与恢复 → 选择 JSON 备份文件」：
   - 服务端先校验文件并列出**同名同校冲突**
   - 每个冲突单独选「新建」或「覆盖」，覆盖要勾选确认
   - 导入前会自动把当前库快照到 `data\backups\pre-import-*.db`
4. 导入完成后重新填一次大模型 API Key（JSON 故意不包含 Key 和模型设置）。

## 四、Tailscale（跨网访问）

**安装脚本不会自动下载 Tailscale**，只检测。没有装时会提示，不影响本机和局域网使用。

1. 新电脑安装 Tailscale：<https://tailscale.com/download/windows>
2. 登录**同一个 Tailscale 账号**（和手机同一 tailnet）。
3. 在项目目录运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy\tailscale-serve.ps1
   ```

   或在安装时已登录的话，`install.ps1` 会自动执行 `tailscale serve --bg http://127.0.0.1:3210`。

4. 脚本会打印 `https://<机器名>.<tailnet>.ts.net`，手机 Tailscale 开着就能打开。

换机器名或换 tailnet 后，重新跑一次 `tailscale-serve.ps1` 获取新地址。

## 五、访问地址

- 本机：`http://127.0.0.1:3210`
- 同一 Wi-Fi 手机：`http://<电脑局域网IP>:3210`
  - 启动窗口会列出局域网地址
  - 也会写到 `logs\access-urls.txt`
  - 或在 PowerShell 执行 `ipconfig`，看「无线局域网适配器 WLAN」的 IPv4 地址
- 跨网：`https://<机器名>.<tailnet>.ts.net`（需 Tailscale）

打不开时先确认：服务在运行、手机和电脑同一 Wi-Fi、防火墙已放行（安装脚本会自动加规则，也可双击 `允许局域网访问.cmd`）。

## 六、安卓 App

- APK 在 `release\StudentStatusBoard-1.0.0.apk`，侧载安装。
- 首次启动会让你填服务器地址，填 `https://<机器名>.<tailnet>.ts.net`。
- 已安装的 App 在加载失败页有「修改服务器地址」入口，换电脑/换地址不用重装。
- App 只接受 HTTPS，所以跨网地址必须走 Tailscale；局域网 HTTP 用手机浏览器打开即可。

## 七、常用参数

```powershell
# 只看计划，不写任何东西
powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1 -DryRun

# 先不配 Tailscale / 不建备份任务
powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1 -SkipTailscale -SkipBackupTask

# 额外注册 Windows 服务（手动启动，不开机自启）
powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1 -InstallService

# 新电脑完全没网：先从旧电脑把 runtime\node 整个目录拷过来
powershell -ExecutionPolicy Bypass -File .\deploy\install.ps1 -SkipNodeInstall
```

脚本幂等：重复执行只会重新配置，不会重复建快捷方式/服务/任务，也不会重置密码和数据。

## 八、忘记登录密码

双击项目根目录的 `重置登录密码.cmd`，或桌面上的「重置登录密码」快捷方式：

1. 输入 `RESET` 确认；
2. 输入新密码两遍（至少 6 位）。

重置后会：

- 旧 `data\config.json` 自动备份成 `data\config.json.bak-<时间戳>`
- 已登录设备退出登录
- 服务器保存的大模型 API Key 清空（加密密钥由密码哈希派生），需要到设置页重新填写
- 学生、反馈、生成历史不受影响

也可以管理员 PowerShell 跑：

```powershell
node scripts\reset-password.js
```

如果提示数据库被占用，先双击 `停止学生状态管理系统.cmd` 停服务，再跑一次。

## 九、验证与卸载

验证：

```powershell
Invoke-RestMethod http://127.0.0.1:3210/api/healthz
# 期望：ok=True db=True
```

卸载（保留 `data\`）：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\uninstall.ps1
```

- 默认停服务、删 Windows 服务、每日备份任务和桌面快捷方式，**保留数据**
- `-RemoveLogs` 清日志，`-RemoveRuntime` 清自动下载的 Node
- `-ResetTailscale` 清 `tailscale serve` 规则
- `-PurgeData` 才会连 `data\` 一起删（需输入 `DELETE` 确认）

## 十、GitHub 更新（可选）

发布包里的 `deploy\release.json` 默认是占位符 `owner/name`，只能用手动更新包：

1. 把新版 `student-status-board-<版本>.zip` 和配套 `version.json` 放进安装目录的 `updates\`
2. 双击 `检查更新.cmd`

配置真实 GitHub 仓库后，`检查更新.cmd` 会自动比版本、下载、校验、停服务、备份、替换、起服务，失败回滚。
